 # 一、简介

**VTJ** 是一个 **基于 Web 的开源项目/工具库**。
 
为了让你更清楚地理解，我们可以从以下几个维度来定义它：

## 1. 它的本质是什么？

- **代码仓库**：它是一堆开源代码（通常托管在 Gitee 或 GitHub 上），包含前端设计器（编辑器）的代码、渲染引擎的代码以及示例项目。
- **Web 应用**：你需要把它下载下来，通过 `n pm install` 安装依赖，然后运行 `npm run dev` 启动。启动后，你会在浏览器中看到一个可视化的编辑界面。
- **开发工具链的一部分**：它是专门给 **Vue 开发者** 用的，用来辅助生成代码。

## 2. 你如何“使用”它？

既然不是安装包，那怎么用呢？通常有两种方式：

- **方式一：本地部署（推荐开发者使用）**
    
    1. 从 Gitee/GitHub 克隆代码到电脑。
    2. 安装 Node.js 环境。
    3. 运行命令启动服务。
    4. 在浏览器打开 `http://localhost:xxxx`，此时你就看到了一个功能完整的“菜单/页面编辑器”。
    5. 你在浏览器里拖拽、配置，然后点击“导出”，它会生成 `.vue` 文件供你下载或复制到项目中。
- **方式二：在线体验（如果有官方演示站）**  
    很多开源低代码项目会提供在线演示地址（Demo），你可以直接在浏览器里试用，但数据通常存在本地缓存，刷新可能丢失，不适合正式生产使用。
    

## 3. 它和“软件”的区别

|特性|VTJ (低代码引擎)|
|---|---|
|**安装方式**|需要配置开发环境 (Node.js, Git)，运行命令行|
|**运行环境**|浏览器 + Node.js 后端服务|
|**用户群体**|**前端开发人员**、全栈工程师|
|**产出物**|**源代码 (.vue)** 或 JSON 配置|
|**修改能力**|可以修改其源码，定制你自己的编辑器|

## 4. 特点

- 如果你想要一个**开箱即用、不用配环境、像 SaaS 一样注册账号就能用**的工具，那通常是**商业低代码平台**（如：宜搭、微搭、JNPF 的商业版等）。
- **VTJ** 是开源的，意味着它是免费的，但需要你自己搭建和维护这个“编辑器”。一旦搭建好，它在浏览器里的操作体验和软件是一样的。

## 前置准备

在开始之前，请确保你的电脑已安装以下环境（这是运行现代 Vue 项目的标准配置）：

1. **Node.js**: 建议版本 `v18` 或 `v20` 以上（推荐使用 `nvm` 管理版本）。

## 第二步：安装依赖(方式二是官方推荐的⭐)
### 方式一：“手动分步安装法”

这是更传统、更透明的开发流程，适合熟悉 Node.js 和命令行工具的开发者。

#### 步骤分解：

1. **自己创建文件夹并进入**
    
    ```bash
    mkdir my-blog && cd my-blog
    ```
    
2. **手动执行 `pnpm create vtj@latest`** （或用 npm）
    - 这会下载脚手架模板到当前目录。
3. **手动运行 `pnpm install`**
    - 安装所有依赖包。
4. **可选：配置国内镜像加速**
    
    ```bash
    pnpm config set registry https://registry.npmmirror.com
    ```
    
5. **关键步骤：先构建再启动**
    
    ```bash
    pnpm build    # ← 注意！这里多了一个“全量构建”
    pnpm dev      # 启动设计器
    ```
    

#### ⚠️ 特点：

- 需要你自己理解每一步的作用。
- “`pnpm build`” 是一个**额外步骤**，用于预编译某些资源（可能是为了优化首次加载速度或生成静态资产）。
- 更灵活，适合定制化管理。

---

### 方式二：“一键脚本初始化法”

这是 VTJ 官方为简化新手体验而提供的“快捷通道”，把多个步骤封装成一个脚本。

#### 步骤分解：

1. **直接用一条命令创建项目**
    
    ```bash
    npm create vtj@latest -- -t app
    # 或者带镜像源
    npm create vtj@latest --registry=https://registry.npmmirror.com -- -t app
    ```
    
    > `-t app` 表示选择 “App 类型” 模板（对应 Web/后台等）
    
2. **进入项目目录后，只需运行两个命令：**
    
    ```bash
    cd your-project-name
    npm run setup     # ← 关键！这个脚本自动完成了 install + build
    npm run dev       # 启动设计器
    ```
    
![[Pasted image 20260323183445.png|643]]

#### 💡 特点：

- `npm run setup` 是一个**自定义脚本**，它内部可能等价于：
    
    ```bash
    pnpm install && pnpm build
    ```
    
- 对用户隐藏了细节，降低上手门槛。
- 特别适合国内用户（提供了淘宝镜像参数）。
- 更符合“低代码平台”的“开箱即用”理念。

### 对比表格总结

|特性|方式一（手动分步）|方式二（脚本初始化）|
|---|---|---|
|创建命令|`pnpm create vtj@latest`|`npm create vtj@latest -- -t app`|
|是否需要手动 install|✅ 是|❌ 否（由 `setup` 脚本完成）|
|是否需要手动 build|✅ 是（`pnpm build`）|❌ 否（由 `setup` 脚本完成）|
|是否支持镜像源配置|✅ 可手动配置|✅ 命令中直接传入 `--registry=...`|
|适合人群|熟悉前端工程化的开发者|新手 / 想快速开始的用户|
|控制粒度|高（每步可控）|低（黑盒封装）|
|最终产物|完全相同|完全相同|

---

### 为什么会有这两种方式？

1. **历史原因**：早期 VTJ 可能只有手动方式，后来为了提升用户体验增加了 `setup` 脚本。
2. **生态兼容**：
    - 方式一更适合用 `pnpm` 的用户（Monorepo 推荐）。
    - 方式二默认用 `npm`，照顾更广泛的开发者群体。
3. **部署场景差异**：
    - 如果你在 CI/CD 环境中自动化部署，可能会偏好方式一（精确控制每一步）。
    - 如果是本地快速原型开发，方式二更高效。

## 2、属性功能

### 🧩 一）、通用属性（所有组件共用）

这些属性适用于 VTJ 中的所有组件，用于基础标识和样式控制。

| 属性名     | 类型            | 说明                                                                                   | 示例/建议                                                       |
| ------- | ------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| `key`   | String        | Vue 的虚拟 DOM key，用于**列表渲染时优化性能或强制重绘**。一般不用手动填，除非动态增删组件。                               | `btn-{{index}}`                                             |
| `ref`   | String        | **给组件起个“名字”**，方便在事件或指令中引用它（类似 HTML 的 id）。                                            | `loginBtn` → 可在事件中用 `this.$refs.loginBtn` 访问                |
| `class` | String        | **自定义 CSS 类名**，用于额外样式覆盖。                                                             | `action-button` → 可在 `<style>` 中定义 `.action-button { ... }` |
| `style` | JSON / String | 直接内联样式，支持对象格式 `{ color: 'red', fontSize: '16px' }` 或字符串 `"color:red;font-size:16px"` | `{ backgroundColor: '#409EFF' }`                            |
| `文本`    | String        | 按钮上显示的文字内容。                                                                          | `立即登录`、`提交订单`、`+ 新增`                                        |

> 💡 提示：`style` 字段右侧有 `...` 按钮，点击可打开 JSON 编辑器，更直观地编写样式对象。

### 🎨 二）、组件专属属性（ElButton 为例）

这些是 Element Plus 按钮组件的核心配置项，决定按钮的视觉风格和行为。

#### 1. 基础外观

|属性|类型|说明|常见值|
|---|---|---|---|
|`size`|Enum|按钮尺寸|`large`（大）、`default`（默认）、`small`（小）|
|`type`|Enum|按钮类型（主题色）|`primary`（主色蓝）、`success`（绿）、`warning`（橙）、`danger`（红）、`info`（灰）|
|`plain`|Boolean|是否朴素按钮（边框+文字，无背景）|✅ 开启后变成空心按钮|
|`text`|Boolean|是否文字按钮（无边框无背景，仅文字）|✅ 适合次要操作如“取消”、“查看详情”|
|`bg`|Boolean|是否保留背景色（配合 `text=true` 使用）|❗ 通常与 `text` 互斥，慎用|
|`link`|Boolean|是否链接按钮（下划线+蓝色文字）|✅ 类似 `<a>` 标签效果|

> 🖼️ 视觉效果对比：
> 
> - `type=primary` + `plain=false` → 实心蓝按钮
> - `type=primary` + `plain=true` → 蓝边白底按钮
> - `text=true` → 纯文字按钮
> - `link=true` → 带下划线的蓝色文字

---

#### 2. 形状与状态

|属性|类型|说明|常见值|
|---|---|---|---|
|`round`|Boolean|是否圆角按钮（两端半圆形）|✅ 适合现代 UI 风格|
|`circle`|Boolean|是否圆形按钮（宽高相等，常用于图标按钮）|✅ 需配合 `icon` 使用，否则只显示文字居中|
|`loading`|Boolean|是否加载中状态（显示旋转图标+禁用点击）|✅ 提交表单时自动开启，防止重复点击|
|`loadingIcon`|Component|自定义加载图标（下拉选择内置图标）|`Loading`、`Refresh` 等|
|`disabled`|Boolean|是否禁用按钮（灰色+不可点击）|✅ 条件满足前禁用，如表单未填写完|

> ⚠️ 注意：`circle=true` 时，按钮会变成正方形，务必搭配 `icon` 使用，否则文字会被裁剪。

---

#### 3. 图标与焦点

|属性|类型|说明|常见值|
|---|---|---|---|
|`icon`|Component|按钮左侧图标（下拉选择内置图标）|`Search`、`Plus`、`Edit`、`Delete` 等|
|`autofocus`|Boolean|页面加载后是否自动聚焦该按钮|✅ 适合弹窗中的“确定”按钮|
|`nativeType`|Enum|原生 button 类型（影响表单提交行为）|`button`（默认）、`submit`（提交表单）、`reset`（重置表单）|
|`autoInsertSpace`|Boolean|是否在图标和文字间自动插入空格|✅ 推荐开启，美观度提升|

> 📌 示例：一个带图标的提交按钮
> 
> ```json
> {
>   "icon": "Plus",
>   "text": "新增文章",
>   "autoInsertSpace": true,
>   "nativeType": "submit"
> }
> ```

---

#### 4. 高级样式（较少用）

|属性|类型|说明|常见值|
|---|---|---|---|
|`color`|String|自定义按钮背景色（覆盖 type 的颜色）|`#ff6b6b`、`linear-gradient(...)`|
|`dark`|Boolean|是否深色模式按钮（暗色背景+浅色文字）|✅ 适合暗黑主题界面|
|`tag`|String|自定义渲染标签（默认是 `<button>`）|`a`（做成链接）、`div`（非语义化）|

> ⚠️ 警告：修改 `tag` 可能破坏无障碍访问（Accessibility），除非特殊需求否则保持默认 `button`。

### 🔄 三）、事件 & 指令

真正的交互能力来自 **「事件」** 和 **「指令」** 标签页：

#### ▶️ 事件（Events）

#### 🎯 概念：什么是“事件”？

> **事件 = 用户做了什么 → 系统响应什么**

比如：

- 用户点击按钮 → 弹出“登录成功”
- 用户双击按钮 → 打开编辑页面
- 用户鼠标悬停 → 显示提示语

在 VTJ 中，你只需在对应事件右侧点击 ✏️ 编辑图标，然后添加“动作”，即可完成逻辑编排。

---

#### 🖱️ 鼠标事件详解（最常用）

##### 1. `click` —— 单击事件（⭐ 最常用）

- **触发时机**：用户用鼠标左键单击按钮。
- **典型用途**：提交表单、跳转页面、弹出对话框、调用接口。
- ✅ 示例：
    - 点击“搜索” → 执行搜索请求
    - 点击“删除” → 弹出确认框 → 确认后删除数据
    - 点击“+ 新增” → 跳转到 `/editor` 页面

> 💡 提示：90% 的按钮功能都绑定在这个事件上！

---

##### 2. `dblclick` —— 双击事件

- **触发时机**：用户在短时间内连续两次单击按钮。
- **典型用途**：快速编辑、展开详情、特殊快捷操作。
- ✅ 示例：
    - 双击“文章标题”按钮 → 直接进入编辑模式
    - 双击“用户头像” → 打开个人资料页

> ⚠️ 注意：移动端不支持双击，慎用！

---

##### 3. `mouseenter` —— 鼠标移入

- **触发时机**：鼠标指针进入按钮区域。
- **典型用途**：显示提示、高亮状态、预加载资源。
- ✅ 示例：
    - 鼠标移到“帮助”按钮 → 显示 tooltip：“点击获取支持”
    - 鼠标移到“下载”按钮 → 预加载文件信息

---

##### 4. `mouseleave` —— 鼠标移出

- **触发时机**：鼠标指针离开按钮区域。
- **典型用途**：隐藏提示、恢复默认样式、取消预加载。
- ✅ 示例：
    - 鼠标离开“帮助”按钮 → 隐藏 tooltip
    - 鼠标离开“预览”按钮 → 停止视频播放

---

##### 5. `mousedown` —— 鼠标按下

- **触发时机**：鼠标按键被按下的瞬间（还未抬起）。
- **典型用途**：拖拽开始、游戏控制、自定义按压效果。
- ✅ 示例：
    - 按住“放大”按钮 → 持续放大图片
    - 按下“录音”按钮 → 开始录制音频

---

##### 6. `mouseup` —— 鼠标释放

- **触发时机**：鼠标按键被释放的瞬间。
- **典型用途**：拖拽结束、完成操作、计算滑动距离。
- ✅ 示例：
    - 松开“放大”按钮 → 停止放大
    - 松开“滑动解锁”按钮 → 判断是否解锁成功

---

##### 7. `mouseover` —— 鼠标经过（含子元素）

- **触发时机**：鼠标进入按钮或其内部任何元素。
- **与 `mouseenter` 区别**：`mouseover` 会冒泡，`mouseenter` 不会。
- ✅ 示例：
    - 鼠标经过带图标的按钮 → 图标变色（即使只经过图标部分）

> 📌 一般推荐用 `mouseenter`，避免意外触发。

---

##### 8. `contextmenu` —— 右键菜单

- **触发时机**：用户在按钮上点击鼠标右键。
- **典型用途**：自定义上下文菜单、快捷操作列表。
- ✅ 示例：
    - 右键点击“文件”按钮 → 弹出“重命名 / 删除 / 分享”菜单
    - 右键点击“图表”按钮 → 显示“导出 PNG / CSV”

> ⚠️ 注意：浏览器默认右键菜单会被阻止，需手动实现自定义菜单。

---

#### ⌨️ 键盘事件详解（辅助交互）

虽然按钮主要靠鼠标操作，但键盘事件可用于无障碍访问或快捷键支持。

##### 9. `keydown` —— 键盘按下

- **触发时机**：任意键被按下时。
- **典型用途**：监听回车键提交、ESC 键关闭、方向键导航。
- ✅ 示例：
    - 在输入框中按 Enter → 自动点击“搜索”按钮
    - 按 Esc → 关闭当前弹窗（如果按钮是“取消”）

---

##### 10. `keyup` —— 键盘释放

- **触发时机**：任意键被释放时。
- **典型用途**：检测组合键、记录按键时长。
- ✅ 示例：
    - 按住 Shift + Click → 多选项目
    - 长按空格键 → 加速滚动（配合 mousedown/mouseup）

---

##### 11. `keypress` —— 字符键按下（已废弃，不推荐使用）

- **说明**：仅针对产生字符的键（如字母、数字），不包括 Ctrl、Alt 等功能键。
- **现状**：现代前端开发中已基本被 `keydown`/`keyup` 替代。
- ❗ 建议：不要使用此事件，兼容性差且语义模糊。

---
#### ▶️ 指令（Directives）略

- `v-if` / `v-show`：条件显示/隐藏
- `v-for`：循环渲染（按钮组）
- `v-bind`：动态绑定属性
- `v-model`：双向绑定（少见用于按钮）

##### 📊 属性速查表

|分类|属性|作用|推荐场景|
|---|---|---|---|
|外观|`type`, `size`, `plain`, `text`, `link`|控制颜色和形态|主要操作 vs 次要操作|
|形状|`round`, `circle`|圆角或圆形|现代化设计 / 图标按钮|
|状态|`loading`, `disabled`|加载或禁用|防止重复提交 / 条件限制|
|图标|`icon`, `loadingIcon`|添加视觉符号|增强识别度|
|行为|`nativeType`, `autofocus`|控制表单行为|提交/重置/自动聚焦|
|样式|`class`, `style`, `color`, `dark`|自定义样式|品牌定制 / 特殊布局|

##### ✅ 实践建议

1. **优先使用 `type` 而非 `color`**  
    → 保持设计系统一致性，避免颜色混乱。
    
2. **重要操作必加 `loading` 状态**  
    → 防止用户重复点击导致数据错误。
    
3. **次要操作用 `text` 或 `link` 按钮**  
    → 降低视觉干扰，突出主要按钮。
    
4. **图标按钮务必设 `circle=true` + `icon`**  
    → 否则文字会溢出或错位。
    
5. **表单内按钮设 `nativeType="submit"`**  
    → 让回车键也能触发表单提交。

## 二）、核心知识点详解 (Key Concepts)

### 1. 组件化架构思想

- **区块 (Block) ≈ Vue 组件**：VTJ 中的区块就是可复用的组件。
- **父子通信机制**：
    - **父传子 (Props)**：页面将数据 (`list`, `item`) 传给区块。
        - _操作_：区块定义属性 -> 页面绑定数据。
        - _注意_：Props 是单向数据流，**严禁在子区块直接修改 Props** (如 `item.done = true` 是错误的)。
    - **子传父 (Events/$emit)**：区块触发事件通知页面更新数据。
        - _操作_：区块内 `$emit('eventName', payload)` -> 页面监听 `@eventName` 并执行方法。

### 2. 数据驱动视图 (Data-Driven)

- **State (状态数据)**：所有动态内容都源于 State。
    - 页面级 State：全局数据 (如 `list` 数组)。
    - 区块级 State：局部临时数据 (如输入框的 `title`)。
- **双向绑定 (v-model)**：
    - 用于表单组件 (Input, Switch)。![[Pasted image 20260326121945.png]]![[Pasted image 20260326122216.png]]![[Pasted image 20260326122023.png]]
    - _重要规则_：绑定对象属性时，不能直接使用可选链 (`?.`)，必须确保对象存在。
    - _修正模式_：若需修改 Props 中的值，必须在父组件通过事件回调来修改源数据，或者在子组件内先拷贝一份本地 State 再绑定。

### 3. 列表渲染与唯一键

- **遍历逻辑**：模拟 Vue 的 `v-for`。
- **Key 的重要性**：在遍历列表时，必须为每一项绑定唯一的 `key` (通常是 `item.id`)，以保证 DOM 更新效率和状态正确性，防止“新增数据导致旧数据状态错乱”的问题。

### 4. 计算属性 (Computed Properties)

- **用途**：用于衍生数据的实时计算，避免在模板中写复杂逻辑。
- **典型场景**：统计总数、筛选已完成数量、格式化字符串。
- **写法**：`return this.props.items.filter(...).length`。
- **依赖**：自动监听依赖数据的变化并重新计算。

### 5. 样式与条件类名

- **动态 Class**：根据布尔值动态添加 CSS 类 (如 `.completed { text-decoration: line-through; }`)。
- **CSS 作用域**：在区块内编写的 CSS 通常只对该区块生效，便于维护。

### 6. 特殊交互处理

- **回车提交**：监听 Input 的 `keypress` 或 `keyup.enter` 事件。
- **空状态处理**：使用 `v-if` 或条件渲染，当 `list.length === 0` 时显示 `ElEmpty` 组件。
